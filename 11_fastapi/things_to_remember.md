# FastAPI Parameter Resolution & Documentation Notes

## Parameter Resolution Rules

FastAPI inspects the type annotations of your function arguments to decide whether a parameter comes from the URL (path or query) or from the HTTP request body (JSON).

FastAPI follows these strict rules:

| Type Annotation | Where FastAPI Looks | Example |
|---|---|---|
| **Pydantic Model** (inherits `BaseModel`) | Request Body (as JSON) | `POST /users` with payload `{"name": "Alice", "age": 25}` |
| **Singular type defined in route path** | Path Parameter | `@app.get("/users/{user_id}")` → `/users/5` |
| **Singular type not in route path** | Query Parameter | `def get_user(limit: int)` → `/users?limit=10` |

## FastAPI Documentation Interfaces

Both `/docs` and `/redoc` are automatic interactive documentation interfaces generated by FastAPI, powered by the exact same OpenAPI JSON schema generated from your Python code (located at `/openapi.json`).

The difference lies in the UI tool, layout, and interactivity:

| Feature | `/docs` | `/redoc` |
|---|---|---|
| **Engine** | Swagger UI | ReDoc |
| **Interactivity** | **Interactive** ("Try it out" button sends live requests) | **Static / Read-only** (cannot execute requests directly) |
| **Layout** | Single-column, expandable accordion list | Three-panel layout (Menu \| Docs \| Code samples) |
| **Best For** | Quick testing & debugging during development | Polished, clean API reference for clients and teams |
